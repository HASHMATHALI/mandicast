# MandiCast — API Specification

Version 0.6 (Phase 4, extended in Phases 5 and 6, 2026-11-27). The OpenAPI document generated by the running API
(`/openapi.json`, browsable at `/docs`) is the reference; this file summarises it and records the decisions behind
it. Changes from the Phase 1 draft are listed in §7.

## 1. Conventions

- Base path `/v1`. JSON only. Dates `YYYY-MM-DD`. Prices in **₹ per quintal** (`"unit": "INR_per_quintal"`).
- Price and forecast responses include `source` (provider, dataset, repository, URL, licence, non-endorsement
  notice) and, where relevant, `data_as_of` (latest arrival date, last successful ingestion).
- Identifiers are the stable integer ids of the dimension tables (`commodity_id`, `state_id`, `district_id`,
  `market_id`); model versions are slugs such as `lightgbm-onion-2026q4-ec32e42e`.
- Lists that can be long are paginated with `limit` (default 50, max 500) and an opaque `cursor`
  (`next_cursor` in the response; `null` on the last page). Keyset pagination: pages stay consistent while data
  is added.
- **Strict parameters:** unknown or repeated query parameters are rejected with 400 (a typo would otherwise be
  silently ignored; repeated values would be ambiguous).
- **Rate limit:** per client, 60 requests per minute by default (`API_RATE_LIMIT_PER_MINUTE`), counted in Redis
  across API workers. Every `/v1` response carries `X-RateLimit-Limit`, `X-RateLimit-Remaining`,
  `X-RateLimit-Reset`; over the limit: 429 with `Retry-After`.
- **Cache:** successful GET responses (except `/v1/health`) are cached in Redis for up to 1 hour, keyed by path,
  sorted query and the id of the latest successful job (ingestion, cleaning or forecast publication), so new data
  is served at once. `X-Cache: HIT | MISS`; `Cache-Control: public, max-age=60`.

### Error format

```json
{"error": {"code": "series_not_found", "message": "No price series for Soyabean at Ashta APMC.",
           "details": {"commodity_id": 1, "market_id": 42}}}
```

| HTTP | `code` | When |
|---|---|---|
| 400 | `invalid_parameter` | Wrong type or range, unknown or repeated parameter, bad cursor, `from` after `to` (the offending value is not echoed) |
| 400 | `date_range_too_long` | Range longer than 5 years |
| 404 | `not_found`, `commodity_not_found`, `market_not_found`, `series_not_found`, `model_not_found` | Unknown path or identifier |
| 422 | `insufficient_data` | Forecast requested for a series without a published forecast; `details.reason` gives the failed sufficiency rule |
| 429 | `rate_limited` | Too many requests |
| 500 | `internal_error` | Unexpected error; `details.request_id` matches the server log, no internals are returned |
| 503 | `model_unavailable` | No forecast published for the commodity |

## 2. Discovery

| Method & path | Purpose | Parameters |
|---|---|---|
| `GET /v1/commodities` | Commodities with series counts, eligible series, date span, `has_forecasts` | `q`, `has_forecasts` |
| `GET /v1/states` | States (cleaned names) with mandi counts | `commodity_id` |
| `GET /v1/districts` | Districts of a state | `state_id` (required), `commodity_id` |
| `GET /v1/markets` | Mandis by name (paginated) | `state_id`, `district_id`, `commodity_id`, `q`, `has_forecast` (needs `commodity_id`), `limit`, `cursor` |
| `GET /v1/markets/{market_id}` | One mandi: every name as reported (with the rule that linked it and the date last seen) and its commodities with first/last report, report days, eligibility | |

## 3. Prices

| Method & path | Purpose | Parameters |
|---|---|---|
| `GET /v1/prices` | Daily history of one (commodity, mandi) series; default range: the 365 days up to its last report | `commodity_id`, `market_id`, `from`, `to`, `variety`, `grade`, `include_flagged`, `limit`, `cursor` |
| `GET /v1/prices/latest` | Latest reported price of each mandi for a commodity | `commodity_id`, `state_id`, `district_id`, `max_age_days` (default 30), `include_flagged`, `limit`, `cursor` |
| `GET /v1/compare` | One commodity at 2–10 mandis on the dates when all reported; default: 90 days | `commodity_id`, `market_ids` (comma-separated), `from`, `to` |
| `GET /v1/trends` | Descriptive statistics (not forecasts): latest vs the averages of the previous 7 and 30 days, 52-week range and position, 91-day volatility of log changes; definitions included in the response | `commodity_id`, `market_id` |

Without `variety`/`grade`, `/v1/prices` returns the primary value of each day (one row per day, chosen without
look-ahead, docs/09). With them, every reported row of that variety/grade. Days without a report are absent, never
filled. Values flagged `local_outlier`, `non_numeric_price`, `zero_or_negative_price`, `min_gt_max`,
`modal_outside_range`, `future_date` or `duplicate_after_normalisation` are left out unless `include_flagged=true`;
other flags (`bounds_not_reported`, `conflict`, `day_has_*`) are informational and returned with the row. Each row
carries `source_observation_id`, the source row exactly as received.

## 4. Forecasts and models

| Method & path | Purpose | Parameters |
|---|---|---|
| `GET /v1/forecasts` | Latest published forecast of a series: one point per day for `horizon` days with 80% and 90% ranges | `commodity_id`, `market_id`, `horizon` (7 or 14, default 7) |
| `GET /v1/forecasts/eligibility` | Whether the series passes the sufficiency rules, the four statistics behind it, and whether it is in the latest publication | `commodity_id`, `market_id` |
| `GET /v1/models/current` | Production model per commodity: version, training cutoff, validity quarter, best iteration, artifact and code SHA-256, latest forecast origin | `commodity_id` |
| `GET /v1/models/{version}/evaluation` | The hold-out evaluation of that model's method against last value and the other models, by horizon and quarter, and the version's promotion-gate result | |
| `GET /v1/models/history` | Every version of a commodity (production, candidate, rejected, archived) with gate outcome and status reason, and the lifecycle events (registered, promoted, rejected, rolled back, fallback) | `commodity_id` (required) |

```json
              "interval_coverage": {"0.8": 0.7797, "0.9": 0.8778}, "report": "docs/10_model_evaluation_report.md"},

 "disclaimer": "Estimate from past prices only (no weather, arrivals or policy data). Not a guarantee of future prices: actual prices can fall outside the range.",

```

(The second point shows a real miss: the reported price fell outside both ranges.)

**Phase 5 fields.** Each point has `served_by` (`model` or `last_value`; the last value is served only when no valid
model exists, methodology C10c as amended) and, when the last value was served, `model_modal_price` (the model's own
value, if any). The response adds `served_by` per day range, `fallback` (for the day ranges shown: the 8-week
comparison of model and last value at publication — points, both WAPEs, `model_lost_recently`, reason), `live_accuracy` (latest live monitoring of published forecasts for that day range;
flagged as not yet reliable below 500 points), `drift` (PSI of the origin's features against the model's
reference) and `accuracy.method` (the hold-out accuracy shown is that of the method that served the requested
horizon). `model` is `null` when no valid model existed and every day shows the last value.

`warnings` is filled when the evaluation was weak for that case: the method did not beat the last price on the
hold-out at that horizon (Tomato, 7 days); hold-out 80% coverage below 75% (Soyabean); the quarter's model stopped
training within 10 rounds, so it is close to the last price (Tomato 2026Q4: 2 rounds); the forecast is more than
14 days old; the last input report is more than 7 days before the origin; days served by the last value (with the
reason); the model lost to the last price over the 8 weeks before publication (informational); feature drift above
the warning threshold.

## 5. Freshness and health

| Method & path | Purpose |
|---|---|
| `GET /v1/freshness` | Last successful ingestion and forecast publication; per commodity: latest arrival date, latest complete date, series reporting in the last 14 days, series that stopped reporting (last report 15–90 days before the latest date), eligible series, latest forecast origin |
| `GET /v1/monitoring` | Operations view (methodology C10): per commodity, the latest live accuracy per day range (model, last value, served; range coverage; direction), the latest publication's fallback decisions and drift, the production model with its gate result, the last 5 lifecycle events, and the missing-update warnings of the last monitor run (`checked_at`) |
| `GET /v1/health` | Database (with latency), Redis, production model artifacts present. 200 `ok` or `degraded` (Redis down: no shared cache or rate limit), 503 `down` if the database is unreachable. Never cached |

## 6. Sign-in and alerts (authenticated) — implemented in Phase 6

Users sign in through the Telegram bot: `/login` returns a one-time link `DASHBOARD_URL/login#code=…` (the code is in
the URL fragment, so it is not sent to servers or written to logs; valid 15 minutes, once). The dashboard exchanges
it for a Bearer session token (30 days). Codes and tokens are stored only as SHA-256 hashes. Every endpoint below
acts only on the caller's own data; another user's alert id behaves like a missing one (404). Responses are never
cached (`Cache-Control: no-store`) and use a separate writable database connection.

| Method & path | Purpose | Responses |
|---|---|---|
| `POST /v1/auth/session` | `{"code": "…"}` → `{"token", "token_type": "bearer", "expires_at"}` | 401 `invalid_code` (invalid, expired or used) |
| `POST /v1/auth/logout` | End this session | 204 |
| `GET /v1/alerts` | My subscriptions | 401 `auth_required` (with `WWW-Authenticate: Bearer`) |
| `POST /v1/alerts` | `{"commodity_id", "market_id", "condition": {"type": "price_above" \| "price_below" \| "forecast_change_pct", "value"}}` | 201; 400 `invalid_value` / `too_many_alerts` (20); 404 `series_not_found`; 409 `subscription_exists` |
| `DELETE /v1/alerts/{id}` | Remove one of my alerts | 204; 404 `alert_not_found` |
| `GET /v1/alerts/history` | Messages sent (or attempted) to me, newest first | 200 |
| `DELETE /v1/me` | Delete my account, sessions, alerts and history immediately | 204 |

Alert messages state facts literally, for example: "MandiCast alert 12: the 7-day forecast for Onion at
Lasalgaon(Niphad) (30 Nov 2026) is ₹4,043/quintal, 1% below the last reported price of ₹4,100. The 80% range is
₹3,738–₹4,575. This is an estimate from past prices, not a guarantee." (Bot commands: docs/13.)

## 7. Changes from the Phase 1 draft

- A series is (commodity, mandi) (methodology §1), so forecasts take no `variety`/`grade`; `/v1/prices` keeps them as
  row filters.
- Location filters use ids (`state_id`, `district_id`) instead of names.
- Intervals: both 80% and 90% ranges per point (`intervals` list) instead of one `interval`.
- Added: `actual_modal_price` on forecast points, `warnings`, `data_complete_through`, `published_at`;
  `has_forecast` filter on `/v1/markets`; `max_age_days` and `include_flagged` on `/v1/prices/latest`.
- `/v1/compare` returns all common dates in the range (at most 5 years) without pagination.
- Validation failures are 400 (`invalid_parameter`); 422 is used only for `insufficient_data`.
